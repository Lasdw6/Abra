# Stage 4 review: iroh default, scoped guests, standing grants (commit ae68fa9)

Reviewer: Grok 4.6 (security-focused)
Repo: `/Users/vividh/Desktop/abra` @ `ae68fa9`
Authoritative: `SPEC.md` (incl. errata), `DESIGN.md`, `docs/API.md`
Method: read-only review of `crates/cadabra`, `crates/abra-cli`, `crates/abra-net`, `crates/abra-core`, and iroh 1.1 `presets::Minimal` / `Builder::empty`. No repo modifications. Morse was not reachable from this environment.

Stage 3’s two-process hole is closed: default transport is iroh, `Daemon::new` fail-closes if the iroh endpoint id differs from the store Ed25519 peer id, store roots are `0700`, the UDS listener probes/locks/`SO_PEERCRED`/1 MiB/30s idle/64 clients, pairing keeps the bootstrap connection open, outbox backoff is real, offer quota is computed from the plan, and extra objects stage outside CAS until the verified closure matches. Those are real fixes. The remaining question is whether the new guest, grant, watch, lease, and session-isolation surfaces are safe enough to be the stable base for an external app that only speaks the public CLI/daemon API.

## Findings

1. **major** — `crates/cadabra/src/lib.rs:276–282`, `crates/abra-net/src/delivery.rs:699`, `743`, `911–924`
   **Defect:** Each incoming connection `DeliveryNode::open`s a private in-memory copy of trust/store and then runs the whole session with a single `now_ms()` captured at spawn. Revoke (`handle` `revoke_token` at `cadabra/src/lib.rs:495–498`) and token expiry are applied to disk / a different node object. The live session keeps the pre-revoke `TrustedPeer` and the pre-expiry timestamp. There is no `type:"revoke"` demux, so `TrustStore::apply_revocation` / `RevocationRecord` are unreachable on the wire (SPEC §7.3 flood is unimplemented).
   **Failure scenario:** A guest (or a custom client using the guest key) holds the bootstrap/trusted connection open. The user runs `abra revoke <token_id>`. New connections fail closed (fresh `DeliveryNode` has no guest, handshake is `bootstrap`, offers are `untrusted`). The existing connection still accepts `offer` / `control` / `plan` using the stale guest record and the frozen `now`. SPEC §7.3 “on revoke: drop the guest, refuse binds/offers both directions” does not hold for the session that matters — the one already open. Expiry mid-session is the same window: a 24h token checked at t=0 remains “valid” on that socket indefinitely.
   **Fix:** Reload trust (or hold a shared `Arc<RwLock<TrustStore>>`) before every authorized frame; sample `now_ms()` per offer/lease/control. On local revoke, close matching connections. Implement signed `revoke` flood (and persist until expiry+7d) so a second full device that later learns the guest via bind-cert cannot keep serving it.

2. **major** — `crates/abra-net/src/delivery.rs:972–986`, `crates/cadabra/src/lib.rs:136–188`, `454–467`, `753–805`
   **Defect:** Guest lifecycle is issuer-local and over-privileged on the guest daemon.
   - `enroll-ok.mesh` is `trust.peers().values().cloned()` — full `TrustedPeer` rows including other guests’ `token_id`, `scopes`, `x25519_pk`, `expires_at`. SPEC §7.2 mesh is `{peer_id,name,role}`. The joiner filters to `Role::Full` (`lib.rs:178–182`) but the leak is already on the wire.
   - Bind certificates are signed and returned to the guest, then never gossiped to other full peers. Combined with finding 1, a guest is only in the intro issuer’s trust store. That accidentally limits blast radius today; it also means `abra enroll` + a second paired laptop cannot talk to the agent, contradicting the mesh the token advertises.
   - `enroll-bind` auto-accepts with no prompt (unlike pairing). Mint always uses `audience: None` (`lib.rs:796`) so the first binder in `bind_by` (≤15 min) wins. Pairing is interactive; enrollment is bearer-token-plus-race.
   - `pair-ticket` / `pair-add` / `enroll-mint` are not gated on `LocalRole::Full`. SPEC §7.2: only full devices mint; guests never pair. A guest daemon is a complete control-API peer.
   **Failure scenario:** (a) Token printed by `abra enroll` is copied from a log; an attacker `abra daemon --token` binds first; the intended agent is `token already bound`. (b) Host user, following the same “copy ticket / pair add” README flow, redeems a pair ticket the guest minted → guest is inserted as `Role::Full` on the host (`accept_pair_request` always uses `Role::Full`) and drops out of every scope check. (c) Joining guest learns every other guest’s token id and scopes from `enroll-ok`. (d) Second user device never receives a bind-cert, so the “mesh” is a lie; revoke on the issuer does not need to flood only because the other device never knew the guest — until someone implements gossip without implementing revoke.
   **Fix:** Gate mint/pair/bind-cert-sign on `LocalRole::Full`. Confirm (or `--yes`) enroll-bind. Prefer `audience` when the guest key is known. Send SPEC-shaped mesh only. Gossip bind-certs to full peers *together with* revocation. Refuse `pair-ticket` on a guest daemon.

3. **major** — `crates/cadabra/src/lib.rs:212`, `264–267`; `crates/abra-net/src/delivery.rs:189`, `212`, `264–267`, `578–587`; README:83–88
   **Defect:** `allow_agent_send` is hardcoded `false` and `handle()` rebuilds a fresh `DeliveryNode` from disk on every control request, which would wipe the flag even if something set it. There is no CLI/API/env switch. SPEC §7.4: send is `token.send && abra.allow_agent_send` (default false, infra-owned). The shipped binaries never turn the switch on. README still documents `enroll --send --receive` then `daemon --token` as the guest path.
   **Failure scenario:** Integrator mints `--send`, starts the agent with `--token`, agent `abra send` hits `enqueue` → `local agent sending disabled`. The scoped-send half of enrollment is unusable from the public surface. Library test `guest_send_requires_scope_and_local_switch` only passes by mutating the field in-process. A showcase agent that is supposed to push handoffs to the user cannot do so without a fork.
   **Fix:** Persist an explicit `--allow-agent-send` (or equivalent) on guest start, default false. Keep `enqueue` / `send_offer_inner` gates. Add mint→bind→in-scope send allowed / out-of-scope denied e2e through the CLI.

4. **major** — `crates/cadabra/src/lib.rs:859–920`, `899–903`, `936–954`, `1089–1100`
   **Defect:** Standing grants are both ineffective on spec-valid data and unsafe if they ever fire.
   - `apply_receive_grants` only walks **unread inbox partials**. SPEC §1.4 / `Manifest::validate_schema` rejects `recipes` on partials (`manifest.rs:211–218`). Full snapshots (the only legal recipe carriers) go to the capsule store (`delivery.rs:404–410`), not the inbox. `auto_run_recipes` is dead for any manifest `RawManifest::parse` will accept. Grant matching itself is exact `peer == from && kind == manifest.kind` (`lib.rs:875–877`) — that part is right.
   - If recipes are ever wired to capsule receives (or a future parser lets a partial through), the executor is `Command::new(&argv[0]).args(argv[1..]).current_dir(cwd).envs(&recipe.env)` with no argv allowlist, no env scrub, no `process_group`. `safe_recipe_cwd` rejects `..` and a final-component symlink but does **not** `canonicalize` after materialize; a tree entry `link → /` plus `cwd: "link/tmp"` resolves outside the dest when the child is spawned (intermediate symlinks are followed). `argv[0]` may be `/bin/sh` or an unqualified name whose `PATH`/`DYLD_INSERT_LIBRARIES` comes from the manifest. `stop_recipes` runs `kill -TERM <pid>` with no start-time check; after daemon restart those pids are reused. SIGTERM shutdown (`RunningDaemon::shutdown`, `lib.rs:77–83`) does not stop recipe children — they orphan.
   **Failure scenario:** (a) Today: `policy grant --auto-run-recipes` appears to succeed; a granted workspace snapshot arrives as `full` and sits in the capsule store; nothing executes. Showcase “agent send, host auto-runs” does not work. (b) After a one-line “also scan capsules / allow recipes on the grant path” fix: a malicious-but-in-scope peer sends a snapshot whose tree contains `escape → /` and recipe `{argv:["/bin/zsh","-c","…"], cwd:"escape/Users/…", env:{DYLD_INSERT_LIBRARIES:…}}`. The grant matches kind+peer, `materialize` writes the symlink (allowed), cwd escapes the dest, and the daemon uid runs attacker argv. Later `abra stop-recipes` may SIGTERM an unrelated process that inherited the recorded pid.
   **Fix:** Apply auto-accept/auto-run to the shelf the snapshot actually landed on (capsule `full` vs inbox `partial`). Constrain `argv[0]` to a binary inside the materialized root (no absolute paths, no PATH search). `clearenv` then set a scrubbed env. `canonicalize` cwd and require `starts_with(dest)`. `setsid` / kill the group; record `(pid, starttime)` and check `/proc` or `sysctl` before kill. Stop recipes on daemon shutdown.

5. **major** — `crates/cadabra/src/lib.rs:313–335`, `crates/abra-net/src/outbox.rs:107–123`, `114–123`
   **Defect:** Outbox work snapshots a detached (non-persisting) `Outbox`, performs the whole dial/transfer, then `sync_entry_from` copies **that one id** back onto the live disk map. Concurrent control ops that reload from disk (`handle` at `lib.rs:428–431` always `DeliveryNode::open`s) can change the same row while the session is in flight. Last merge wins. `pending_ids` + 100ms worker no longer hot-loops (backoff + skip `Failed` is correct; `outbox.rs:156–164`, `196–214`, unit test `pending_selection_respects_backoff_and_preserves_failure`) — the spin is fixed — but the merge is not atomic with cancel/retry/expire.
   **Failure scenario:** User `abra cancel <id>` while `send_offer` is in `AwaitingAck`. Cancel persists `Cancelled`. Session then `apply_ack` + `sync_entry_from` overwrites the row to `Acked` (or `Queued` after `fail_attempt`). Duty that was explicitly cancelled completes, or a failed attempt’s backoff is lost and the worker retries immediately. Two pending entries are serialized on one worker so same-id double-send is unlikely unless a future second worker appears; cancel/expire vs in-flight send is the live hole.
   **Fix:** Compare-and-swap on merge (refuse to clobber `Cancelled`/`Expired`/`Acked`). Or hold a per-id lock from `pending_ids` through `sync_entry_from`. Persist transitions on the live outbox (not a shadow copy) and keep only the byte copy detached.

6. **major** — `crates/cadabra/src/lib.rs:406–423`, `911–915`, `1103–1110`; `crates/abra-net/src/delivery.rs:368–380`, `896`
   **Defect:** `watch` is a 100ms poll of the entire `net/events.ndjson` with no rotation, no byte cap, no idle timeout after the first reply, and `sent` reset to 0 if the file shrinks (full replay). Every inbox arrival and every `control` message (including `instruct` text) is appended. Watch connections never return to the 30s idle limiter; they only count against the 64 client semaphore.
   **Failure scenario:** A chatty peer (or the local user leaving `abra watch` up) grows `events.ndjson` without bound; each watch client rereads/resends the prefix every 100ms. 64 watchers × a multi-hundred-MB log is a local DoS. A truncated/replaced log replays history to subscribers that assumed a live tail (event-loss semantics are “replay everything,” undocumented). Control `instruct` bodies land in a file any same-uid UDS client can dump via `events`.
   **Fix:** Size-capped ring (or rotate). Tail with `seek` + inode check; document replay-on-rotate. Idle-timeout watch or require an explicit subscription cap. Do not log control plaintext at info; emit `{op,nonce,from}` only.

7. **minor** — `crates/abra-net/src/transport.rs:385–386`, `418–434` vs `249–253`; `crates/abra-net/src/auth.rs:349–368`, `325–331`
   **Defect:** Identity binding at bind time is sound: iroh `SecretKey::from_bytes` is the same 32-byte Ed25519 seed, `IrohTransport::local_peer_id` is `endpoint.id()`, `Daemon::new` (`cadabra/src/lib.rs:90–92`) refuses a mismatch. Handshake `check_hello` requires `hello.peer_id == connection.peer_id()` (`auth.rs:1079–1082`). TCP `dial` additionally requires `connection.peer_id() == requested`. **Iroh `dial` does not.** `add_peer_address` deserializes an `EndpointAddr` and stores it under the *ticket* peer id with no check that `EndpointAddr`’s endpoint id equals that key. `PairAccept` is unsigned (SPEC §7.1). `complete_pair_as_joiner` inserts `ticket.peer_id` from that unsigned accept.
   **Failure scenario:** A ticket issuer signs `peer_id=A` with an `EndpointAddr` whose id is `V`. Joiner maps `A → V`, `connect`s V (TLS identity V), still inserts A. Subsequent `dial(A)` keeps hitting V. A third-party MITM cannot forge the signed ticket, so this is issuer-controlled redirection (A is already the party you chose to pair with) — not a silent impersonation of an honest A. It is still the exact check TCP already does and DESIGN’s “cannot diverge” claim at runtime.
   **Fix:** After `wrap`, require `connection.peer_id() == peer`. Reject `EndpointAddr` whose id bytes ≠ map key. Same check on enrollment intro addresses.

8. **minor** — `crates/abra-net/src/transport.rs:152–153`, `365–370`; `crates/cadabra/src/main.rs:11–42`; `DESIGN.md:8–22`; iroh 1.1 `endpoint.rs:190–196`, `presets.rs:59–78`
   **Defect:** TCP cannot silently become the path: it is `--transport tcp` only, binds `127.0.0.1:0`, and iroh `add_peer_address` JSON-parses `EndpointAddr` (a `tcp://` hint fails closed). Good. Default iroh uses `presets::Minimal` on `Builder::empty()`, which is **no address-lookup services and no relay transport** (`RelayMode::Disabled`). `n0` relays / `iroh.link` Pkarr are not on. That matches DESIGN’s “direct-address, pure p2p” default. DESIGN also says relays “may be configured for internet reachability”; Abra exposes no relay/discovery knobs, so two NATed showcase machines with only EndpointAddr UDP hints will often fail to connect unless they are on the same LAN. Tickets/tokens carry the full serialized `EndpointAddr` (direct IPs, relay URL *if* one were present). That is connectivity metadata, covered by the ticket signature; it leaks LAN/public IPs to whoever holds the ticket — expected, should be documented as such. `relay_key` is not stuffed into pair tickets (`None` at mint).
   **Failure scenario:** External demo on two home networks: pair tickets exchange, iroh has no relay/discovery, `pair add` hangs until timeout. Operators may switch to `--transport tcp` thinking it is a WAN fallback; it is localhost-only cleartext (authenticated). Not a MITM downgrade, but a footgun.
   **Fix:** Keep TCP opt-in and localhost-only. If internet p2p is in scope for the showcase, add an explicit `--relay` (self-hosted or n0) rather than implying Minimal already hole-punches globally. Document that tickets contain IP hints.

9. **minor** — `crates/cadabra/src/lib.rs:1006–1038`, `973–1004`; `crates/abra-core/src/capsule.rs:259–334`
   **Defect:** Auto-renew opens a *second* `DeliveryNode` from disk every 60s and writes `Refresh` epoch+1 if local holder and expiry ≤ now+5min. `lease-take` uses the mutex node and writes `Takeover` epoch+1. `accept_lease` treats same-epoch/same-prev as a signature-byte race and otherwise parks losers in `evidence` (`Ok(false)`). Renew after a successful takeover (holder ≠ local) is skipped — good. Renew vs in-flight takeover can still both read the same parent and race; coordination-not-enforcement is SPEC §5, so this is not authz bypass, but the daemon can bounce the winning lease depending on which write lands last. Guests cannot take (`lease_acquire`/`lease_takeover` forced false at mint, `lib.rs:785–786`) — good. Revoke does not drop a lease the guest somehow held (they cannot acquire).
   **Failure scenario:** Host `lease take` while the 60s renew on the previous holder (or the same node’s stale disk snapshot) writes a `Refresh` with the same epoch. One record becomes evidence; `lease-status` may briefly disagree with the other device. Showcase “takeover stops the agent” has no `lease-update` push to the losing holder (`delivery.rs` has no `lease-update` handler) — SPEC §6.8.
   **Fix:** Serialize lease writes on one node lock. Push `lease-update` to the previous holder. Reload trust before `authorize_lease`. Test take vs renew.

10. **minor** — tests: `crates/cadabra/tests/e2e.rs` (2 tests, both `yes: true`, loopback), `crates/abra-cli/tests/two_process.rs` (1 iroh pair+partial send+accept), `crates/abra-cli/tests/smoke.rs` (UDS oversize + status on TCP), `crates/abra-net/tests/net_spec.rs` (library scope/ack/genesis; `guest_send_requires_scope_and_local_switch` is in-process)

    **Failure scenario:** A daemon that breaks interactive confirm, enroll-bind, or grant execution still ships green on “62 tests.” The two-process iroh test is the only OS-process proof of teleport; it does not prove the features this stage added.
    **Fix:** CLI-level tests: `pair confirm` without `--yes`; `enroll`/`--token` in-scope send (once finding 3 exists) and out-of-scope reject; revoke then offer denied on a *kept-open* connection; `policy-grant` auto-accept of a partial and auto-run of a full; concurrent A↔B send; `status` during a large receive.

## Priority checklist (task items)

**1. iroh integration security.** Ed25519-as-`SecretKey` is sound and fail-closed at `Daemon::new`. Handshake binds `hello.peer_id` to the TLS/iroh remote id. Tickets/tokens carry `EndpointAddr` (IPs); that is signed connectivity data, not a key leak. TCP is explicit, localhost-only, and cannot be selected by tampering an iroh ticket. Default discovery/relay is Minimal/empty = no n0 relays, no Pkarr; DESIGN is truthful about the default and overstates “relays may be configured” (no Abra knob). Missing dial-time EndpointAddr id check is finding 7.

**2. Cross-user guest lifecycle.** Mint no longer silently inserts `*`. Join/bind is wired. Scope checks exist on enqueue, incoming offer, local-guest receive, and `have` (cleared entirely for a guest sender — stricter than SPEC, not a disclosure). They are not applied to an already-open session after revoke/expiry (finding 1). Guests cannot send from the shipped CLI (finding 3). Guests can mint pair tickets and enrollment tokens on their own daemon (finding 2). No bind-cert gossip, no revoke flood. Guest-to-guest offer is denied when both roles are visible in the *same* trust store.

**3. Standing grants / recipes.** Matching is exact kind AND peer. Execution path is inbox-only, so spec-valid recipes never run; the executor is unsafe against cwd/env/argv/pid tricks if it is later hooked to `full` snapshots (finding 4). `materialize` still rejects dest symlinks/`..` names for the tree write itself.

**4. New daemon surface.** Watch is an unbounded poll-tail (finding 6). Lease renew does not fight takeover by holder check, but races on disk snapshots and does not notify the loser (finding 9). Control is signed, full-peer-only, nonce-replayed for 10 minutes, timestamp-windowed — using the same frozen `now` as the rest of the session. SIGTERM stops the four supervisor tasks and unlinks the socket; it does not join per-connection sessions or recipe children.

**5. Hotfix verification.** `--yes` inserts on accept and treats a later `pair-confirm` as idempotent if the peer is already trusted. Interactive path waits up to 600s on an approval file and completes the *same* connection; pending/approved are on disk so restart + `pair confirm` + retry can work. Still no `yes: false` UDS test. Outbox no longer spins. Snapshot-then-merge can lose cancel (finding 5).

**6. Test adequacy.** Named stage-3 gaps still missing. Guest/grant e2e “not completed” is still not completed; the library unit tests do not substitute for daemon-level bind/scope/revoke/grant.

## SPEC-critical invariants (spot check)

**Byte authority.** Live `send` still signs then `RawManifest::parse`s canonical bytes; `validate_incoming_offer` still hashes the received `manifest_raw`. Preserved.

**Verified ack.** `apply_ack` still verifies the `ack` domain against the intended recipient. Health-check now accepts reconnect acks (`OutboxState::Healthcheck`); pending-ack files are unlinked after a successful write (`delivery.rs:892–895`). Stage-3 finding 7 is addressed on the happy path.

**Guest scope.** Checks in `validate_incoming_offer` / `enqueue` are real and not bypassed; they are incomplete across session lifetime, mesh install, and the send switch (findings 1–3).

**Materialize escape.** Still the accept primitive; dest emptiness / non-symlink preserved. Recipe cwd is a new escape hatch around it (finding 4).

**TCP downgrade.** Not possible without both sides passing `--transport tcp`.

## Overall verdict

**Not ready to be the stable base for an external showcase app built only on the public CLI/daemon surface**, if that app needs scoped guests, standing recipe grants, or two devices plus an agent. It *is* ready enough for a same-LAN two-device “pair + send partial + accept” demo over iroh (the `two_process` test), with `--yes` pairing and no grants.

What landed is a real v1 skeleton: encrypted default transport with identity glued to the device key, lockdown of the store/socket, pairing that can complete on both sides, outbox backoff, closure staging, SIGTERM on the supervisor tasks. What is advertised in README / API.md as the rest of v1 — `enroll --send`, `daemon --token`, `policy grant --auto-run-recipes`, revoke, watch, lease takeover as a control plane — is either unwired, issuer-only, unsafe, or untested.

### Top-3 must-fix

1. **Guest session + enrollment honesty (findings 1–3):** re-validate trust/`now` per frame and close on revoke; stop guests from minting pair tickets; do not put other guests’ token rows on `enroll-ok`; either implement bind-cert+revoke flood or document “guest talks only to the issuer.” Ship `--allow-agent-send` so `--send` tokens can actually send, with CLI e2e for in-scope/out-of-scope/revoke.
2. **Standing grants that match the shelf they apply to, with a sandboxed executor (finding 4):** auto-run on `full` capsule snapshots (or stop advertising it); never `Command` a peer-supplied argv/env/cwd without dest-containment. Kill process groups on `stop-recipes` and on SIGTERM.
3. **Outbox merge + tests (findings 5, 10):** CAS-safe sync so cancel/expire cannot be overwritten by an in-flight session; add the deferred bidirectional, status-during-receive, interactive-pair, and guest/grant e2e tests. Until those exist, treat stage 4’s new surface as unproven.
